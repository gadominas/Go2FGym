# Blueprints

Go2FGym follows the shared blueprints in https://github.com/gadominas/app-blueprints.
The script's `BLUEPRINTS` block is the source of truth; this table mirrors it and adds deviations.

| Blueprint | Version | Since app version | Deviations |
| --- | --- | --- | --- |
| [in-app-updates](https://github.com/gadominas/app-blueprints/blob/in-app-updates-v1.0.0/blueprints/in-app-updates.md) | 1.0.0 | 1.7.0 | The page's update hook is `HG.showUpdate`; `window.__showUpdate` (the blueprint's name) calls it. Introduced in 1.5.0 and brought fully in line in 1.7.0 |
| [settings](https://github.com/gadominas/app-blueprints/blob/settings-v1.0.0/blueprints/settings.md) | 1.0.0 | 1.7.0 | The Settings icon sits in the Train tab header (the other screens have back bars); "Sans serif" keeps Go2FGym's condensed headline font; sheet CSS is scoped under `#cfgsheet` because the app already uses `.seg`, `.chip` and `.row`; the old colour names are kept as aliases of the shared tokens, plus app colours `--done` and `--p-iron` per palette; the other weight-plate colours are fixed artwork; equipment is a list of switches (at least one stays on) and a change rebuilds the library when Settings closes; changing the weight unit reloads the page when Settings closes; the page bridge is a message queue, so the Scriptable side answers with `HG.onSettings` |
| [ai-configuration](https://github.com/gadominas/app-blueprints/blob/ai-configuration-v1.0.0/blueprints/ai-configuration.md) | 1.0.0 | 1.6.0 | The “after each workout” jobs (analysis and Strava post) share the one What AI does switch; the default Strava tone is in Settings › AI coach |
| [launch-screen](https://github.com/gadominas/app-blueprints/blob/launch-screen-v1.0.0/blueprints/launch-screen.md) | 1.0.0 | 1.11.0 | The logo is tilted, so its parts sit in one `<g transform="rotate(-20 120 112)">` inside the launch screen SVG (the part classes and their CSS are unchanged); Pop is the two lime plates and Detail the two white outer plates; the Sweep is two motion lines in one path; the name uses the app's `--display` font (`--sp-font`); the splash script is the first statement of the page's only `<script>`, before the start-up block (`window.__parts`, `window.__boot`), because the page script is `webApp.toString()`; the app's `.spark` and `.spark-mark` classes were renamed `.trend` and `.ai-mark` (the blueprint reserves `sp`) |
| [widgets](https://github.com/gadominas/app-blueprints/blob/widgets-v1.0.0/blueprints/widgets.md) | 1.0.0 | 1.12.0 | `widgetModel()` sets no `at`, so the amber "⟳ Updated …" footer never shows and `widgetStaleMin` (kept in Settings › Widget like every app) has no effect here: workouts change only inside the app, which saves the snapshot each time, and the widget works out Today/Yesterday and the week when it draws. Before the first snapshot (the first widget run after updating) the model reads `history.json` in local Documents, read-only. Muscle groups come from a Scriptable-side copy of the page's muscle-to-group map (`W_GROUPS`), because the page code can't be shared |
| [ai-invitation](https://github.com/gadominas/app-blueprints/blob/ai-invitation-v1.2.0/blueprints/ai-invitation.md) | 1.2.0 | 1.13.0 | `inviteIfDue` chains on Go2FGym's own update check (it shows the sheet with `window.__showUpdate`; there is no `offerUpdate`) and saves with `saveSettings()` (the blueprint's `saveAll()`); the page reports with Go2FGym's queued `send("aiinvite", { v })`. `window.canInvite` holds the card back until the disclaimer is accepted, during a workout (a session with exercises, rest timer included) and while the library downloads, so on a first launch it appears only if the disclaimer is accepted within the 20 s it waits, otherwise on the next launch. The busy check also waits for the exercise preview (`#pv`). After **Turn on AI**, the **Add key** pulse looks for `[data-aiact="aikey"]` (Go2FGym's AI sheet marks its buttons `data-aiact`) and is put back for 2.6 s, because the sheet draws itself again when its state arrives from Scriptable. `aiInviteKeyRemoved()` runs in `airm` after the provider switch, so a key left with the other provider still counts |

## Recipes

Coding rules every app follows (https://github.com/gadominas/app-blueprints/tree/main/recipes). They describe how the code is written, not a feature, so they aren't listed in the script's `BLUEPRINTS` block or in Built with.

| Recipe | Version | Since app version | Deviations |
| --- | --- | --- | --- |
| [safe-startup](https://github.com/gadominas/app-blueprints/blob/safe-startup-v1.0.0/recipes/safe-startup.md) | 1.0.0 | 1.13.0 | Settings live in iCloud (`load()` with the 10 s limit, `settingsOk` set in `loadSettings()`); workouts, the draft, the disclaimer, AI settings and usage are local files, so their guard is in `writeJSON` (`USER_FILES`), `saveHistory` (also covers the iCloud backup) and `aiWrite` instead of one `write()`. The exercise library (`exercises.json`, `library-meta.json`, photos) is a download, not your data: it is read in `loadData()` but never blocks saving and can always be fetched again. The one iCloud read of data is the history backup restore, also limited to 10 s. The list handed over in pieces is the exercise library (`st.lib`, slices of 100), the biggest message; the workout history goes in `window.__boot`. The page reads the state as `window.__INIT` (was `window.__BOOT`). The bridge is a message queue, so `main()` collects the page's messages every 200 ms while the window is open instead of only awaiting it, and `ev()` limits each collection to 5 s; the Start-up log row asks with `send("startlog")` and Scriptable answers with `HG.onStartLog`. `loadData(true)` in the widget branch reads only the workouts (no backup restore, since a widget never writes, and no library). No `saveAll()` at close: every change is saved when it is made. Deferred work: the widget snapshot at 0.7 s (Go2FGym has no refresh on open). The 1.7.2 watchdog stays only for a page that stops answering after it has booted: it builds the page again and hands the state over (at most 3 times per run); opening is covered by the recipe |
